## 소개

weeknote는 매일의 업무를 자유롭게 적고, 주 단위로 돌아볼 수 있는 웹 앱입니다. 날짜별 카드에 메모를 쌓고, 프로젝트 태그로 내용을 나누어 주간 보고에 활용할 수 있습니다.

> 현재는 프런트엔드 프로토타입입니다. 메모는 메모리에만 보관되어 **새로고침하면 초기화**됩니다. 화면의 `AI 정리`는 프로젝트별 분류를 제공하며, 실제 AI 모델을 호출하지 않습니다.

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| 주간 업무 보드 | 월~일 세로 열에 메모를 쌓고, 드래그로 날짜와 순서를 변경합니다. |
| 인라인 Markdown | 제목, 목록, 굵은 글씨 등을 입력하는 자리에서 바로 적용합니다. |
| 프로젝트 태그 | `@프로젝트명`과 `@[프로젝트 이름]`으로 메모를 분류합니다. |
| 주간 정리 | 선택한 주의 내용을 프로젝트별로 묶고 일반 텍스트로 복사합니다. |
| 테마와 반응형 화면 | 라이트·다크 테마와 반투명 글라스 패널과 가로 스크롤 칸반 보드를 지원합니다. |
| 키보드 접근성 | 모달 포커스 관리, Escape 닫기, 동작 줄이기 설정을 지원합니다. |

날짜는 한국 시간 기준입니다. 이번 주에서는 오늘이, 다른 주에서는 월요일이 기본 선택됩니다.

## 시작하기

### 준비

- Node.js **22.12 이상**
- pnpm **11.19.0** (`package.json`의 `packageManager` 기준)
- Git

### 설치 및 실행

```sh
git clone https://github.com/dongle-zzang/week-note.git
cd week-note
pnpm install --frozen-lockfile
pnpm dev
```

브라우저에서 [localhost:3000](http://localhost:3000)을 엽니다. 현재 버전은 별도 서버나 환경 변수 없이 실행할 수 있습니다.

## 사용 방법

1. 주간 보드 또는 원하는 요일 열에서 **+ 메모 추가**를 선택합니다.
2. 날짜를 고르고 Markdown으로 업무 내용을 작성합니다.
3. 프로젝트별 분류가 필요하면 줄 시작에 태그를 넣습니다.
4. 카드의 이동 손잡이를 드래그해 다른 요일로 옮기거나 같은 요일에서 순서를 바꿉니다. 키보드는 Space → 방향키 → Enter로 이동하며 Escape로 취소합니다.
5. **AI 정리**로 주간 내용을 확인하고 **전체 복사**로 가져갑니다.

```markdown
@프로젝트A
- 로그인 화면 개선
- 사용자 피드백 반영

@[프로젝트 B]
- 배포 일정 검토
- 다음 주 작업 정리
```

태그 아래의 내용은 다음 태그가 등장할 때까지 해당 프로젝트에 속합니다. 태그 앞의 내용은 미분류로 묶이며, 이메일과 코드 안의 `@`는 태그로 처리하지 않습니다.

## 개발하기

### 명령어

| 명령어 | 용도 |
| --- | --- |
| `pnpm dev` | 개발 서버 실행 |
| `pnpm typecheck` | Vue·TypeScript 타입 검사 |
| `pnpm test` | 날짜, 태그 분류, Markdown 처리 테스트 |
| `pnpm build` | 프로덕션 빌드 |
| `pnpm preview` | 빌드 결과 미리보기 |
| `pnpm generate` | 정적 사이트 생성 (`apps/web/.output/public`) |

### 프로젝트 구조

```text
apps/
└── web/
    ├── app/
    │   ├── components/   # 주간 보드, 메모 편집기, 정리 모달
    │   ├── composables/  # 메모 상태, 주 이동, 테마
    │   ├── types/        # 업무 메모 타입
    │   ├── utils/        # 날짜, 프로젝트 분류, Markdown 처리
    │   └── assets/       # 공통 스타일
    ├── public/           # 정적 파일
    ├── tests/            # 기능 테스트
    ├── .env.example      # 값이 없는 환경 설정 양식
    └── nuxt.config.ts
```

Nuxt 4.5.2와 Vue 3를 사용하며, `ssr: false`로 브라우저에서 실행합니다. 편집기는 Tiptap, Markdown 렌더링은 markdown-it을 사용합니다. 원시 HTML과 위험한 링크는 실행하지 않으며, 외부 이미지 문법은 텍스트로 표시합니다.

### 다른 컴퓨터에서 이어서 작업하기

처음에는 위의 설치 절차로 저장소를 복제합니다. 이후 작업을 시작하기 전에 최신 코드를 받습니다.

```sh
git pull --ff-only
pnpm install --frozen-lockfile
```

작업을 마치면 변경 내용을 확인하고 커밋하여 업로드합니다.

```sh
git status
git add <변경한-파일>
git diff --cached
git commit -m "변경 내용 설명"
git push
```

의존성을 변경했다면 `pnpm-lock.yaml`도 함께 커밋합니다. 로컬 환경 설정은 각 컴퓨터에서 별도로 준비합니다. 메모 데이터의 기기 간 동기화는 아직 지원하지 않습니다.

## 환경 설정과 민감 정보

서버 연결을 추가할 때에는 설정 양식을 복사한 뒤, 실제 값을 복사본에만 입력합니다.

```sh
cp apps/web/.env.example apps/web/.env
```

`.env.example`의 항목은 향후 연동을 위한 예시입니다. 현재 앱은 이 값을 사용하지 않으며, 실제 연동 시 환경 변수를 읽는 코드를 추가해야 합니다.

| Git에 포함 | Git에서 제외 |
| --- | --- |
| 소스 코드, 문서, 테스트 | `.env`, `.env.*`의 실제 환경 설정 |
| 값이 없는 `.env.example` | `local/` 안의 서버 주소·접속 설정·업무 데이터 |
| 패키지 설정과 잠금 파일 | 개인 키, 로컬 DB, 의존성, 빌드 결과, 캐시 |

실제 서버 IP, 사내 URL, 비밀번호와 API 키는 `.env` 또는 루트의 `local/`에 보관합니다. **`.gitignore`는 파일을 제외하는 규칙이므로 소스나 문서에 직접 쓴 비밀값은 보호하지 않습니다.**

이미 커밋한 파일은 제외 규칙만 추가해도 이전 이력에 남습니다. 비밀값을 업로드했다면 해당 값을 교체하고, 필요에 따라 추적과 Git 이력을 정리해야 합니다.

브라우저에 전달한 설정과 요청 URL은 사용자에게 보입니다. 향후 AI나 외부 API를 연결할 때 비밀키는 별도 서버에서 관리합니다.

## 확장 지점

| 파일 | 연결할 기능 |
| --- | --- |
| `useWorkEntries.ts` | 메모 조회·저장 API와 영구 저장 |
| `WeeklyWorkEditor.vue` | 실제 AI 정리 호출 |
| `types/work.ts` | 메모 데이터 모델 확장 |
| `utils/projects.ts` | 프로젝트 태그 해석과 분류 로직 |

`apps/*` workspace 구조를 사용하므로, 향후 `apps/api`를 추가하여 인증·저장·AI 연동을 구현할 수 있습니다.
